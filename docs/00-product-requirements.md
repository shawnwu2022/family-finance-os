# 产品需求规格（PRD）

## 1. 核心用户故事

### 随时记账
- 作为用户，我消费后能在手机上手工、文字或截图记账。
- 截图识别必须让我确认金额、账户、分类、时间后再入账。
- 每月底我能导入微信/支付宝/京东/银行账单进行校验。

### 随时查财务
- 我能看到本月收入、支出、结余、储蓄率、净资产。
- 我能看到“安全可消费金额”，并知道它为什么是这个数字。
- 我能查询最近一段时间哪些分类/商户推动了支出变化。

### 管预算
- 我能给分类或目标设月预算。
- 系统能告诉我已用、剩余、预计月底以及超支风险。
- 预算不会把信用卡还款重复算成消费。

### 解债务
- 我能录入房贷、车贷、信用卡、消费贷等合同参数。
- 系统能比较最低还款、Avalanche、Snowball、自定义提前还款。
- 系统不会为了最小化利息把应急现金压到家庭设定底线以下。

### 做目标
- 我能设置应急资金、买车、首付、旅游、教育、退休等目标。
- 系统能给出目标需要的月度拨款和预计达成时间。
- 多目标冲突时系统给出取舍，不假装所有目标都能同时实现。

### 问 AI
- 我可以问“这个月还能花多少”“最近为什么花多了”“现在买 8000 元电脑合适吗”“先还哪笔债”。
- AI 必须调用 Finance Tool 获取数值，而不是自行计算。
- 重大建议显示事实、假设、替代方案和不确定性。

## 2. V1 UX 原则

- 记账路径优先使用 ezBookkeeping 的成熟移动 PWA，不重复造移动客户端。
- Finance Core PWA 首页优先显示：净资产、本月结余、储蓄率、Safe-to-Spend、应急资金月数、债务余额/风险、预算风险、AI 输入框。
- 普通查询目标响应路径短；复杂规划允许更慢但必须显示“正在计算/使用的数据截止时间”。
- 手机是一级客户端，不是桌面网页的缩小版。

## 3. 非功能需求

| 属性 | V1 要求 |
|---|---|
| 可用性 | 单 VPS，允许人工恢复，不做 HA |
| 可访问性 | 公网 HTTPS，手机/PC |
| 安全 | 2FA、最小暴露、Secret 不入 Git、DB 不公网 |
| 可恢复 | 每日备份 + 本地异地副本 + 恢复演练 |
| 正确性 | 财务引擎单元测试；关键指标可追溯 |
| 性能 | 家庭规模数据下交互无明显阻塞；先测再优化 |
| 可维护 | 1 个自研应用、1 个账本应用、1 个 DB、1 个反代 |
| 可扩展 | P40/OpenClaw/MCP/HA 通过 Adapter 增量加入 |

## 4. 非目标

- 不替代持牌会计、税务、法律或投资顾问；
- 不自动买卖证券；
- 不自动调银行资金；
- 不做多家庭公开 SaaS；
- 不逆向银行接口获取账户密码/验证码；
- 不把 LLM 输出当财务事实。
